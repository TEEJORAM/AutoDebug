Use AutoDebug

Let an AI agent set breakpoints, run and step through your program in VS Code or Cursor on Windows, macOS or Linux, and write a report. The same steps are in the repository at site/index.html.

Nothing runs until you click Approve in the IDE. AutoDebug drives the debugger in VS Code and Cursor through the AutoDebug Bridge extension (verified with automated tests and the real Python debugger; first real-IDE run pending). CLion, Visual Studio and Xcode are not supported yet, and autodebug config does not write CLion, Visual Studio or Xcode files.

Windows

PowerShell. Python 3.11 or newer (py), Git, and VS Code with the Python extension.

1. Install

git clone https://github.com/TEEJORAM/AutoDebug.git
cd AutoDebug
py -m pip install -e .
py -m autodebug doctor

2. Install the AutoDebug Bridge

py -m autodebug bridge install vscode

Then in VS Code: Developer: Reload Window; the status bar shows AutoDebug. Use cursor instead of vscode for Cursor. If code is not on PATH, install the printed .vsix with Extensions → ··· → Install from VSIX….

3. Connect a project

The sample project first; later, your own folder. This writes that project's MCP config and keeps other servers.

py -m autodebug config vscode --write examples\AutoDebugDemo
py -m autodebug config cursor --write D:\Projects\MyApp

Practice debugger instead (no extension, no approval):

py -m autodebug config vscode --demo --write D:\Projects\MyApp
py -m autodebug config cursor --demo --write D:\Projects\MyApp
py -m autodebug config claude-desktop --demo --write
py -m autodebug config claude-code --demo

Reports go into the project's autodebug-reports folder; raw evidence stays in %LOCALAPPDATA%\autodebug.

macOS

Terminal. Python 3.11 or newer, Git, and VS Code with the Python extension.

1. Install

git clone https://github.com/TEEJORAM/AutoDebug.git
cd AutoDebug
python3 -m venv .venv
source .venv/bin/activate
pip install -e .
autodebug doctor

Run source .venv/bin/activate again in each new terminal.

2. Install the AutoDebug Bridge

autodebug bridge install vscode

Then in VS Code: Developer: Reload Window; the status bar shows AutoDebug. Use cursor instead of vscode for Cursor. If code is not on PATH, install the printed .vsix with Extensions → ··· → Install from VSIX….

3. Connect a project

The sample project first; later, your own folder. This writes that project's MCP config and keeps other servers.

autodebug config vscode --write examples/AutoDebugDemo
autodebug config cursor --write ~/Projects/MyApp

Practice debugger instead (no extension, no approval):

autodebug config vscode --demo --write ~/Projects/MyApp
autodebug config cursor --demo --write ~/Projects/MyApp
autodebug config claude-desktop --demo --write
autodebug config claude-code --demo

Raw evidence stays in ~/Library/Application Support/autodebug.

4. Debug with the agent

  1. Open the project folder in VS Code (for the sample: examples/AutoDebugDemo inside AutoDebug).
  2. Command Palette → MCP: List Servers → autodebug → Start Server (or Restart Server).
  3. Open Copilot Chat in Agent mode and ask:
Help to debug AutoDebugDemo using the autodebug tools. Bug: moving a shape changes its area (the "Debug tests" launch configuration shows it). Choose breakpoints in the code that computes the area, request my approval, then step through it to find the cause. Finish the case with the problem, root cause, solution and evidence, and tell me where the report is.

VS Code shows a dialog listing the launch configuration, breakpoints and limits. Click Approve. The agent stops at geometry.py line 15, steps through the loop and writes autodebug-reports/DEMO-AREA-MOVE.md.

Cursor, Claude Code and Claude Desktop

Cursor: config cursor --write creates .cursor/mcp.json; enable autodebug under MCP in Cursor Settings. Claude Code: run the claude mcp add command that config claude-code prints. Claude Desktop: restart it after config claude-desktop --write. All of them drive the bridge in the VS Code or Cursor window that has the project open.

Practice debugger

Use the autodebug tools to investigate case AUTODEBUG-DEMO: show its status, the stack, and the variables local_var and password.

With --demo you get a synthetic stack, local_var = 42 and password = ***REDACTED***. Case AUTODEBUG-DEMO is built in, not your application; its approval lasts 30 minutes.

examples/AutoDebugDemo is a small Python and C++ program with one deliberate area bug (geometry.py line 15). The security gate (T05) is open only for the VS Code / Cursor bridge.

If something fails

What you seeWhat to do
No AutoDebug Bridge is running for …Open exactly that folder in VS Code with the extension installed; check the AutoDebug status bar item. bridge status lists windows.
No dialog appearsIt may be behind another window. AutoDebug Bridge: Show Log lists each request.
TIMEOUT while startingAsk the agent for max_operation_seconds 20–30.
PLAN_CHANGEDA file the plan names changed after approval; start a new case.
No autodebug toolsRe-run config … --write from the AutoDebug folder, then restart the MCP server.
is not plain JSONThe existing file has comments. Run config without --write and paste the entry yourself.
APPROVAL_EXPIRED with --demoThe 30-minute demo approval ended. Restart the server.
