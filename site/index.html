AutoDebug

Let the AI agent in Cursor or VS Code debug your program with the IDE's own debugger, then explain the root cause in a written report. Nothing runs until you click Approve.

From a real session in Cursor: four corners, three passes. The edge from (2, 2) back to (2, 1) is never added, so the moved square reports area 2 instead of 1.

Overview #

AutoDebug connects your AI agent to the debugger you already use. The agent reads your code, picks breakpoints and asks to run one of your launch configurations. After you approve, it builds the program, stops at the breakpoints and steps through the code. When it understands the fault, it writes the report into your project.

It investigates
Each step reports which variables changed. A trace records every pass through a line, before and after it runs. The report keeps a timeline of everything the debugger showed.
You stay in control
Every debug session needs your click on Approve, in a dialog that shows exactly what will run. Step and time limits apply. The agent cannot evaluate code or change variables.
It stays on your machine
The extension listens on 127.0.0.1 only, behind a random token. No account, no cloud service, no dependencies.
It uses your setup
Your launch configurations and build tasks in .vscode, and any language your IDE can debug.

Set up #

You need Python 3.11 or newer, Git, and Cursor or VS Code with the debugger extension for your language. For Python, that is Python and Python Debugger.

  1. Install AutoDebug and connect it to your IDE. Use setup vscode for VS Code.

    git clone https://github.com/TEEJORAM/AutoDebug.git
cd AutoDebug
py -m pip install -e .
py -m autodebug setup cursor
    git clone https://github.com/TEEJORAM/AutoDebug.git
cd AutoDebug
python3 -m venv .venv
.venv/bin/python -m pip install -e .
.venv/bin/python -m autodebug setup cursor

    setup installs the AutoDebug extension in the IDE and adds the autodebug MCP server for all your projects.

  2. In the IDE, open the Command Palette and run Developer: Reload Window. The status bar shows AutoDebug.

  3. Turn on the server. In Cursor: Cursor Settings, MCP, then switch on autodebug. In VS Code: MCP: List Servers, autodebug, Start Server.

autodebug doctor checks all of this. To update later, run git pull in the AutoDebug folder, then setup again.

Your first session #

The repository includes examples/AutoDebugDemo, a small program with one deliberate bug: moving a shape changes its area. Open that folder in the IDE and ask the agent, in Agent mode:

Help me debug AutoDebugDemo: moving a shape changes its area. Use the autodebug tools to find the root cause and write a report.

Click Approve when the IDE asks. The agent stops in polygon_area, traces the loop and writes its report to autodebug-reports/.

Approving a session #

When the agent starts a session, the IDE shows a dialog with its goal, the build command, the program and arguments, the breakpoints, and the step and time limits. Approve runs exactly that, once. Closing the dialog, or two minutes without an answer, refuses. A message in the chat is never an approval.

Breakpoints you set yourself in the editor stay in place. The agent sees them listed as editor breakpoints, and can run past them to a line it chooses.

Agent tools #

ToolWhat it does
list_targetsLaunch configurations and build tasks in the open project
start_sessionAsks for approval, builds if needed, sets breakpoints, launches and waits for the first stop
stepOver, into or out, up to 20 times, with the variables that changed
continueRuns to the next stop, or past other breakpoints to a chosen line
traceRuns to a line repeatedly and records each variable before and after it runs
inspect, stackLocal variables of a frame, and the call stack
breakpointsAdds or removes breakpoints during the session
wait, pause, stop_sessionFollows, interrupts or ends the session
write_reportWrites the root-cause report with a timeline of the session

Reports #

Each report is a Markdown file in autodebug-reports/ in your project. It states the problem, how the program was run, a numbered timeline of every stop, step and trace, the root cause with its confidence, the solution and how it was verified. A cause marked confirmed must say how it was confirmed. Values that look like secrets appear as ***REDACTED***.

Your own project #

AutoDebug runs the launch configurations in your project's .vscode/launch.json, and optionally a build task from .vscode/tasks.json first. If the program prints to the terminal, set "console": "internalConsole" so the agent can read its output when it ends. Use a test or a small reproduction, never a production system or real customer data.

How it works #

The agent talks to the autodebug MCP server, a small Python program the IDE starts. The server talks to the AutoDebug extension inside the IDE window over a token-protected local connection. The extension drives the IDE's debugger through the public VS Code API and the Debug Adapter Protocol. The full contract is in docs/design.md.

Safety #

  • One approval covers one debug session and exactly what the dialog showed.
  • No expression evaluation and no changes to variables.
  • Variables and output that look secret are redacted before the agent or the report sees them.
  • Only 127.0.0.1, with a random token. Breakpoint files must be inside the project.
  • What the agent reads may be sent to its model provider, as with any AI agent. Debug only code and data you are allowed to share with it.

Troubleshooting #

What you seeWhat to do
No window is running the AutoDebug extensionOpen the project folder in the IDE and check for AutoDebug in the status bar. Run autodebug setup if it is missing.
No debugger for type "debugpy"Install the Python Debugger extension in the IDE and reload the window.
No dialog appearsIt may be behind another window. AutoDebug: Show Log lists each request.
The agent uses an old serverRun autodebug doctor; it points out old entries and how to fix them.
