AutoDebug

An AI agent debugs your program with the debugger of VS Code, Cursor or Visual Studio, then writes the root cause in a report. Nothing runs until you click Approve.

From a real session: four corners, three passes. The edge from (2, 2) back to (2, 1) is never added, so the moved square reports area 2 instead of 1.

What it is #

AutoDebug has two parts. A small extension runs inside each IDE window and controls that IDE's debugger. A Python program gives AI agents the debugging tools, through MCP or the terminal. The agent asks to run one of your launch configurations, you approve it in the IDE, and the agent builds, stops at breakpoints, steps, reads variables and writes a report into your project.

  • IDEs: VS Code, Cursor, Visual Studio 2022 and 2026.
  • Agents: Cursor's agent, Claude Code, GitHub Copilot in VS Code and in Visual Studio, and any other agent with MCP or a terminal.
  • Languages: whatever the IDE's debugger runs: C++ and Python in VS Code and Cursor; C++ in Visual Studio.

Connect in 2 minutes #

  1. If you use Visual Studio, close it. Then install AutoDebug and run setup:

    py -m pip install git+https://github.com/TEEJORAM/AutoDebug.git
py -m autodebug setup
    python3 -m venv ~/.autodebug
~/.autodebug/bin/python -m pip install git+https://github.com/TEEJORAM/AutoDebug.git
~/.autodebug/bin/python -m autodebug setup

    setup finds every IDE and agent on the computer. It installs the AutoDebug extension in VS Code, Cursor and Visual Studio, and adds the autodebug MCP server to VS Code, Cursor, Visual Studio and Claude Code.

  2. Do the one step setup prints for your IDE. They are listed under Steps per IDE.

  3. Check with py -m autodebug doctor (macOS and Linux: ~/.autodebug/bin/python -m autodebug doctor). It lists the connected IDEs, the open IDE windows and anything to fix.

Optional, per project: py -m autodebug setup C:\path\to\project also writes an AutoDebug section into the project's AGENTS.md, so agents know the terminal command when their app hides the MCP tools.

Steps per IDE #

VS Code

  1. Command Palette → Developer: Reload Window. The status bar shows AutoDebug.

  2. If VS Code asks whether to trust or start the autodebug server, allow it.

Cursor

  1. Command Palette → Developer: Reload Window. The status bar shows AutoDebug.

  2. Cursor Settings → Customize → MCPs → autodebug → turn it on. Cursor starts every new MCP server switched off. The entry then shows a green dot.

  3. Start a new chat. A chat that was already open does not get the tools.

Visual Studio 2022 and 2026

  1. Start Visual Studio and open your solution. View → Output → AutoDebug says it is listening.

  2. Set the startup project and choose the Debug configuration. Its debug settings become the launch configuration the agent uses. For a CMake project, paths are relative to the CMake source folder.

  3. For Copilot in Visual Studio only: in the chat, Tools → tick autodebug. Visual Studio starts MCP tools switched off. Cursor's agent and Claude Code need nothing more.

Claude Code

Nothing. setup adds the server to ~/.claude.json; start a new Claude Code session.

Which agent, which IDE #

The agent and the IDE are separate. Any connected agent can debug in any IDE window that runs the AutoDebug extension. Cursor's agent can debug a C++ program in Visual Studio, and Claude Code can debug in Cursor.

When windows of more than one IDE are open, name the IDE in the prompt, for example "use the Visual Studio window".

Debug #

Open the project in the IDE and ask the agent, for example:

The app crashes when I delete the last item in a list. Use the autodebug tools: build the Debug configuration, stop where the item is removed, find the root cause and write a report.

Try it first on examples/AutoDebugDemo in the repository: moving a shape changes its area, in C++ and in Python.

The Approve dialog #

When the agent starts a session, the IDE shows a dialog with its goal, the build command, the program and arguments, the breakpoints, and the step and time limits. Approve runs exactly that, once. Closing the dialog, or two minutes without an answer, refuses. A message in the chat is never an approval.

In Visual Studio the dialog stays on top of other windows. In VS Code and Cursor it opens in the IDE window; switch to it.

No tools in the chat #

Some apps drop MCP tools from a chat without an error. The agent can then run the same tools in its terminal, in the same debug session:

py -m autodebug run list_targets ide=visualstudio
py -m autodebug run help

Values need no JSON: breakpoints=geometry.cpp:16, variables=total,i. setup with a project folder writes the exact command for your computer into the project's AGENTS.md.

Reports #

Each report is a Markdown file in autodebug-reports/ in the project. It states the problem, how the program was run, a numbered timeline of every approval, build, stop, step and trace, the root cause with its confidence, and the fix. Values that look like secrets appear as ***REDACTED***.

How it works and safety #

The agent calls the autodebug MCP server, or autodebug run in a terminal. Both reach one AutoDebug service on your computer, which holds the debug session and its report, and talks to the extension in the IDE window over 127.0.0.1 with a random token. The extension shows the Approve dialog and runs only what you approved. The full contract is in docs/design.md.

  • One approval covers one debug session and exactly what the dialog showed.
  • No expression evaluation and no changes to variables.
  • Values that look secret are redacted before the agent or the report sees them.
  • Only 127.0.0.1, with a random token. Breakpoint files must be inside the project or folders you list.
  • What the agent reads goes to its model provider, as with any AI agent. Debug only code and data you are allowed to share with it.
