AutoDebug

An AI agent debugs your program with the debugger of VS Code, Cursor or Visual Studio, then writes the root cause in a report. Nothing runs until you click Approve.

From a real session: four corners, three passes. The edge from (2, 2) back to (2, 1) is never added, so the moved square reports area 2 instead of 1.

What it is #

AutoDebug has two parts. A small extension runs inside each IDE window and controls that IDE's debugger. A Python program gives AI agents the debugging tools, through MCP or the terminal. The agent asks to run one of your launch configurations, you approve it in the IDE, and the agent builds, stops at breakpoints, steps, reads variables and writes a report into your project.

  • IDEs: VS Code, Cursor, Visual Studio 2022 and 2026.
  • Agents: Cursor's agent, Claude Code, GitHub Copilot in VS Code and in Visual Studio, and any other agent with MCP or a terminal.
  • Languages: whatever the IDE's debugger runs: C++ and Python in VS Code and Cursor; C++ in Visual Studio.

Install #

You need Python 3.11 or newer. If you use Visual Studio, close it first. Then, in a terminal:

py -m pip install --upgrade autodebug
py -m autodebug setup
brew install pipx
pipx ensurepath
pipx install autodebug
autodebug setup
sudo apt install pipx
pipx ensurepath
pipx install autodebug
autodebug setup

On Windows, py is the Python launcher, so nothing has to be added to your PATH; write py -m autodebug wherever this page says autodebug. On macOS and Linux, open a new terminal after pipx ensurepath. autodebug setup finds VS Code, Cursor, Visual Studio and Claude Code on the computer, connects each one, and prints the few steps left for you. They are in the IDE sections below.

autodebug doctor checks everything at any time: which AutoDebug runs and from where, the connected IDEs, the open IDE windows, and whether a newer version is on PyPI. Setup and doctor always print commands in the form that works on your computer, such as py -m autodebug doctor on Windows.

To update, run setup again (py -m autodebug setup on Windows). When PyPI has a newer AutoDebug, setup installs that exact version first, replacing every file of the old copy, then reconnects your IDEs with it. Nothing else to do; --no-update skips it.

VS Code #

Before you start

  • C++: the C/C++ extension or CodeLLDB. Python: Python and Python Debugger.
  • A launch configuration that debugs your program in .vscode/launch.json, and optionally a build task in .vscode/tasks.json. If you can start it with F5, AutoDebug can run it.

Connect

  1. Run autodebug setup (see Install). It installs the extension and adds the autodebug server to VS Code.

  2. Command Palette → Developer: Reload Window. The status bar now shows AutoDebug.

  3. Open the Copilot chat in Agent mode. In its tools list, make sure autodebug is ticked. If VS Code asks whether to trust or start the server, allow it.

Check

autodebug doctor lists a VS Code window open line with your project folder.

Debug

  1. Ask the agent, for example:

    Use the autodebug tools to find why moving a shape changes its area. Build first, stop in polygon_area, trace total, and write a report.

  2. VS Code shows the Approve dialog. Read it (see Debug safely) and click Approve within 2 minutes.

  3. The agent builds, stops, steps and traces. The report is written to autodebug-reports/ in the project.

Cursor's agent and Claude Code can debug in a VS Code window too. Name it in the prompt when another IDE is open: "use the VS Code window".

Cursor #

Before you start

  • C++: CodeLLDB. Microsoft's C/C++ debugger does not run in Cursor. Python: Python and Python Debugger.
  • A launch configuration in .vscode/launch.json (Cursor reads the same files as VS Code).

Connect

  1. Run autodebug setup. It installs the extension; Cursor keeps it updated from Open VSX.

  2. Command Palette → Developer: Reload Window, in every Cursor window. The status bar shows AutoDebug.

  3. Nothing to turn on: the extension registers the server with Cursor itself. Cursor Settings → Customize → MCPs shows extension-autodebug with a green dot.

  4. Start a new chat in Agent mode. A chat that was already open does not get the tools.

Check

autodebug doctor lists a Cursor window open line. If it says an mcp.json entry "still starts autodebug", run autodebug setup cursor: an old entry makes Cursor show the server switched off.

Debug

  1. Ask the agent in the new chat, for example:

    Use the autodebug tools with launch configuration "Debug C++ (CodeLLDB)". Find why moving a shape changes its area and write a report.

  2. Cursor shows the Approve dialog in its window. Click Approve within 2 minutes.

  3. The report is written to autodebug-reports/ in the project.

Cursor's agent can also debug in Visual Studio: open the solution there and say "use the Visual Studio window (ide: visualstudio)".

Visual Studio 2022 / 2026 #

Before you start

  • The Desktop development with C++ workload. C++ only; Python in Visual Studio is not supported yet.
  • A solution whose startup project runs your program. For CMake, generate one first, for example cmake -S . -B build\vs.

Connect

  1. Close every Visual Studio window, then run autodebug setup. It installs the extension and adds the server for Copilot in Visual Studio.

  2. Start Visual Studio and open the solution. View → Output, choose AutoDebug: it says it is listening.

  3. Set the startup project and the Debug configuration. Their debug settings become the launch configuration the agent sees, for example geometry (Debug|x64).

  4. Pick the agent:

    • Cursor's agent or Claude Code: nothing more to do.
    • Copilot in Visual Studio: in the chat, Tools → tick autodebug. Visual Studio starts MCP tools switched off.

Check

autodebug doctor lists a Visual Studio window open line with the solution's folder.

Debug

  1. Ask the agent, and name Visual Studio when Cursor or VS Code is open too:

    Use the autodebug tools with the Visual Studio window (ide: visualstudio) and launch configuration "geometry (Debug|x64)". Build first, stop at geometry.cpp line 16, trace total, and write a report.

  2. The Approve dialog opens on top of your other windows. Click Approve within 2 minutes; unanswered, it closes and nothing runs.

  3. Visual Studio builds and starts the program. A breakpoint shows as not bound until the program has loaded; that is normal.

For a CMake project, paths are relative to the CMake source folder (geometry.cpp, not cpp/geometry.cpp). If the agent reports NOT_BUILT, the program has not been built yet; it retries with the build task it names.

Claude Code #

Nothing to do after autodebug setup: it adds the server to ~/.claude.json. Start a new Claude Code session, open the program in VS Code, Cursor or Visual Studio, and ask as above, naming the IDE.

Debug safely #

The Approve dialog shows the goal, the build command, the program and its arguments, the breakpoints, and the step and time limits. Approve runs exactly that, once.

  • Read before you click. Approve only a program, build command and arguments you expect. Closing the dialog, Deny, or two minutes without an answer refuses.
  • A chat message is never an approval. Only the dialog in the IDE starts anything.
  • The agent cannot change your program's state. No expression evaluation and no changes to variables. Values that look secret are hidden from it.
  • Use test data. Debug a test or a small reproduction, never a production system or real customer data. What the agent reads goes to its model provider.
  • It stays local. AutoDebug listens on 127.0.0.1 only, with a random token, and collects no data. Setup and doctor only ask PyPI for the newest version number.

No tools in the chat #

Some apps drop MCP tools from a chat without an error. The agent can then run the same tools in its terminal, in the same debug session:

autodebug run list_targets ide=visualstudio
autodebug run help

To tell agents this for a project once: autodebug setup <project folder>. It writes the command into the project's AGENTS.md.

Troubleshooting #

What you seeWhat to do
The agent has no autodebug toolsStart a new chat. Cursor: MCPs should show extension-autodebug with a green dot. Copilot: tick autodebug in its tools. Any agent can use autodebug run.
No window is running the extensionOpen the project in the IDE. VS Code and Cursor: Developer: Reload Window. Visual Studio: View → Output → AutoDebug.
No Approve dialogSwitch to the IDE window. "No answer within 2 minutes" means nobody clicked; ask the agent to try again.
NOT_BUILTThe agent retries with the build task it names.
"pipx" or "autodebug" is not recognizedWindows: use py -m pip install --upgrade autodebug and py -m autodebug. macOS and Linux: run pipx ensurepath and open a new terminal.
"Requirement already satisfied" and setup behaves like an old versionRun py -m autodebug setup (or autodebug setup): it replaces the old copy with the newest version itself. autodebug doctor shows the version that runs.
Doctor says a newer AutoDebug is availableRun setup; it installs the new version and reconnects everything.
Setup says Visual Studio is openClose every Visual Studio window and run autodebug setup again.
No debugger for type "…"Install that debugger extension (see the IDE's "Before you start") and reload the window.

Commands #

CommandDoes
